## Direct-source remediation

The family adapter never constructs a missing presentation. It supports these
strict, source-bound routes:

- exact declared note rows and totals under the Family-32 owner;
- one exact primary-income-statement Family-32 result when the activity note
  is genuinely not observed;
- exact same-document primary-result unit corroboration for an otherwise
  unitless note, without changing any coefficient;
- an exact terminal source result when it closes the declared component
  frontier; and
- authenticated PDF-visible source repair applied to a private page clone
  before query/evaluation.

The primary-result query now ignores balance-sheet trading-securities
provision rows, which are controls for a different accounting population. It
is blocked by an actual Family-32 income/expense activity population. The
topology likewise no longer treats the investment-securities provision label
as a Family-32 trading-securities role. Duration columns require the explicit
policy `DISTINCT_SUFFIX_AFTER_EXACT_COMMON_PREFIX`; an ambiguous or
non-distinct axis fails closed.

The registered repair artifact has 30 exact page repairs: 48 cells and one
money-column classification over ABB 2, BVB 9, EIB 2, KLB 6, NVB 2, SGB 2,
SHB 2, STB 1, and VAB 4 sources. Every repair binds source SHA/size, selected
page-JSON ID, physical page, RGB 300-dpi PNG render SHA, table/row/column, and
the exact before-image. The 20 newly registered primary-result repairs are
literal printed dashes for BVB 23–25, 28, 29, 31–33, 35; KLB 53, 54, 57, 61;
NVB 112, 117; SGB 147, 152; SHB 173, 175; and STB 205. A repair never routes
by bank, filename, ordinal, note number, or value.

Visible dashes are source-observed zero. A genuinely blank cell stays typed
`BLANK_SOURCE_CELL` with `coefficient=null`; an all-blank role is omitted.
Totals corroborate or veto observations and never infer a blank child.
Independent display-unit rounding is available only through the explicit
family policy and only for a scaled unit; VND remains exact.
